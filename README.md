# 悬浮翻译 Android 原生第一版（0.3.0）

目标设备：荣耀 200 Pro，按 MagicOS 10.0 的使用路径设计。

## 这版已经包含

- 原生首次设置页：悬浮窗权限、后台活动提醒、荣耀设置关键词。
- 原生悬浮按钮，可以拖动。
- 悬浮按钮使用 specialUse 前台服务，系统会显示一条常驻通知，减少被 MagicOS 清理的概率。
- 第一次点击“译”后调用系统屏幕捕获授权；本次悬浮翻译会话内复用同一个屏幕捕获会话，不再每次弹窗。
- MediaProjection 前台服务保持一个受系统通知保护的会话，但**只在点击“译”之后到取到一帧为止的这段时间里真正接收屏幕画面**：其余时间投射目标的输出 surface 是断开的，应用收不到任何屏幕内容。
- 关闭悬浮按钮、主界面停止按钮或系统停止共享后释放全部屏幕读取资源。
- 捕获当前帧后在设备端运行 Latin OCR，再使用 ML Kit 英译中模型翻译，面板展示本次真实识别结果并支持复制。
- OCR 模型随 APK 提供；英译中模型首次使用时按需下载，后续可在本机翻译。

## 真实翻译的边界

本版本不再包含固定的演示句子。点击“译”后，链路是：截取当前帧 → Bitmap → ML Kit Latin OCR → ML Kit 英译中 → 悬浮面板。

首次英译中需要联网下载约 30 MB 的本地模型；下载后翻译文本不需要上传到服务器。受保护页面、DRM 内容、密码页或系统禁止捕获的界面，Android 可能只返回空白画面，此时应用会明确提示失败，不会伪造结果。

## 关于网络和隐私

**屏幕上识别出的文字不会离开设备，也不会离开本应用进程。** OCR 和英译中都在端侧完成，识别结果只在进程内部从 ML Kit 直接交给悬浮面板显示，不经过任何广播、文件或网络。

但要如实说明：`INTERNET` 权限不只用于下载翻译模型。ML Kit 附带的 Google 库默认开启使用统计上报（Firelog / datatransport），并使用一个 Firebase 安装标识（FID）。这部分**不包含屏幕文字**，但确实会周期性地向 Google 发送使用事件。当前使用的 ML Kit 版本没有提供公开的关闭开关，要彻底去掉只能更换 OCR / 翻译方案。ML Kit 同时会带入一条源码中没有声明的 `ACCESS_NETWORK_STATE` 权限。

复制按钮写入的译文会被标记为敏感内容（Android 13+ 不再弹出内容预览气泡），并在关闭悬浮按钮时清除。结果面板带 `FLAG_SECURE`，其他应用无法截图或录到它。

## 荣耀 200 Pro / MagicOS 10 首次设置

1. 在应用内点“去开启”，允许“显示在其他应用上层”。
2. 在系统设置搜索“应用启动管理”，找到“悬浮翻译”，关闭自动管理并允许后台活动。
3. 打开最近任务，把“悬浮翻译”卡片下拉加锁，避免系统清理悬浮按钮。
4. 在英文应用里第一次点悬浮按钮“译”。系统会询问是否允许捕获屏幕；这是 Android 的系统保护提示。允许后，在本次会话里再次点击不会重复询问。
5. 第一次真正翻译时保持网络可用，让英译中模型完成下载；下载期间不要连续点击悬浮按钮。
6. 不需要屏幕读取时，回到应用点“关闭悬浮按钮”；这会同时停止悬浮窗和屏幕捕获服务。

荣耀不同小版本的设置页面文字可能略有差异，因此应用内使用“搜索关键词”引导，不把某一个固定菜单层级写死。

## 构建

每次向 `main` 或 `claude/**` 推送都会触发 GitHub Actions 构建，产物是一个名为 `floating-translator-apk` 的 artifact，可在对应的 workflow run 页面下载；run summary 里会打印 APK 的 SHA-256，便于核对下载到的文件。

本地构建：

```
./gradlew assembleRelease
```

Gradle Wrapper 已固定为 8.14.3，CI 会用 Gradle 官方发布的校验和校验 `gradle-wrapper.jar`。`gradle/wrapper/gradle-wrapper.properties` 里的 `distributionSha256Sum` 还是 TODO，文件内注明了取值命令，建议在有网络的机器上补齐后再用于正式发布。

### 签名

release 构建没有配置 `signingConfig`，所以 CI 产出的是**未签名 APK，不能直接安装**。两种做法：

1. 在仓库 Settings → Secrets 里配置 `KEYSTORE_BASE64`（keystore 文件的 base64）、`KEYSTORE_PASSWORD`、`KEY_ALIAS`、`KEY_PASSWORD`，CI 会自动 zipalign + 签名，并打印签名证书指纹。
2. 下载未签名 APK，自己用 `apksigner` 签。

**必须使用与 0.2.1 相同的签名密钥**（证书 SHA-256 见下），否则无法覆盖安装，需要先卸载旧版。

## 关于 dist/ 里的安装包

> **`dist/FloatingTranslator-0.2.1-MagicOS10-RealOCR-ARM64.apk` 是 0.2.1 的旧包，不包含 0.3.0 的任何安全修复。**
>
> 它仍然是持续镜像整个屏幕的旧实现，识别文字仍然经系统广播传递，剪贴板也没有敏感标记。安装前请用上面的命令重新构建。

该 APK 只保留 ARM64 原生库，面向 Honor 200 Pro 减少体积；不兼容仅支持 ARM32 的老设备。目标 SDK 35、最低 Android 8.0。签名证书 SHA-256 指纹：

## 仍需在实体手机确认的部分

当前构建环境没有连接实体荣耀 200 Pro，也装不了 Android SDK，因此 0.3.0 从未被编译成 APK，更没有真机跑过。不能把 MagicOS 10 的后台保活、具体应用的受保护页面和首次模型下载说成已真机通过。

0.3.0 最需要先验证的一点：屏幕捕获改成了按需挂载 surface，即 `VirtualDisplay.setSurface(null)` 暂停、再挂上新的 `ImageReader` 恢复。这是文档化的用法，但没有在该机型上实测。**如果这一步在该机型上不工作，表现是第一次点击正常、之后每次点击都超时并重新弹授权。** 其余待验证项见 `SECURITY-RED-BLUE-REPORT.md`。

安装后应先在普通英文网页或设置页验证，再测试 Claude 等目标应用。
